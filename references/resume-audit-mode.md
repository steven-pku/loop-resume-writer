# Resume Audit 模式（招聘侧 / 第三方审阅）

> 本模式与主流程（候选人侧）反向：审阅者**无法**跟候选人建账本、无法核实声称。产出是**审阅报告 + 面试追问清单**，不是改写稿。
> 触发：用户是招聘方/HR/面试官，拿他人简历要评估，说「帮我看这份简历/评估候选人/这人靠谱吗/该不该约面」。
> 边界：本模式给结构化审阅信号，不替代招聘决策；不做背调，不臆断候选人动机。

## 与候选人侧的三点反转

| 维度 | 候选人侧（主流程） | 招聘侧（本模式） |
|---|---|---|
| 事实来源 | 账本（本人给定，可追问补全） | 声称清单（无法核实，只能标「需举证」） |
| 真实性维度作用 | 帮本人标注自己的待核项 | 帮审阅者标出**该在面试追问**的项 |
| 产出 | 优化后的简历 | 审阅报告 + 追问清单（→ 喂 loop-interview-writer 设计验证面试） |

## 工作流

### 1. 去噪
忽略平台导出水印（「仅供招聘专用」等）、候选人 ID 串、下载时间戳、二维码占位——这些是平台生成的噪声，不是简历内容。

### 2. 目标画像（Gate 降级）
招聘侧通常有明确岗位。无完整 JD 时接受降级：用岗位名 + 薪资段 + 已知岗位要求构造粗画像，报告顶部显式标「JD 正文缺失，按岗位画像粗匹配」，匹配判断相应留余地。

### 3. 声称清单（替代账本构建）
逐条提取简历声称，两分类标注：
- **可核实类**：教育/证书/任职时间线/公司名——面试或背调可查。
- **需举证类**：量化成果、角色定位（主导/负责/参与）、技能熟练度自评——只有候选人本人能证，审阅阶段一律按「待验证」对待。

### 4. 审阅打分（audit rubric，见下）
### 5. 产出审阅报告（模板见下）

## Audit Rubric /100（招聘侧专用，含候选人侧没有的任期维度）

| 维度 | 分 | 要点 |
|---|---|---:|
| 岗位匹配度 | 25 | 主线经历与目标岗位的直接相关度；相关经历占比 vs 无关经历 |
| 成果可信度 | 25 | 有量化且**合理** vs 大词通胀（「行业标杆」「高热度爆品」无数字）；量化的可举证性 |
| 真实性风险 | 20 | inflated 声称（如技能使用月数超出年龄/工龄）、时间线空档、学历性质未披露、自述工龄 vs 可见工作史差额 |
| 稳定性与连续性 | 15 | 任期模式（近期是否连续短任期）、职业路径连贯性、空档 |
| 表达质量信号 | 15 | 对设计/文案岗：简历本身的排版/错别字/信息组织＝候选人真实能力的旁证；纯职责腔 vs 成果表达 |

> 岗位无关时表达质量维度权重下调、成果可信度上调，由审阅者按岗位性质微调（在报告里说明）。

## Fatal flags（不是淘汰，是「必须面试澄清否则高风险」）

- 自述工龄与可见工作史差额显著且无解释
- 核心量化成果全是大词无数字
- 关键时间线断裂/重叠
- 技能/成就声称物理上不合理（如熟练月数 > 从业月数）
- 学历性质可能被模糊化（在职期间取得的学位未注明统招/成教/网教）

## 审阅报告模板

```markdown
## 简历审阅 · {候选人代号} · 目标岗位 {岗位}
（JD 状态：完整 / 仅岗位名画像）

### 匹配总览
- Audit 分：{N}/100（可比排序用）
- 一句话结论：{强/中/弱匹配 + 最关键理由}

### 可信优势（分「可核实」与「候选人声称待验证」两栏）
- 可核实：
- 声称待验证：

### 🚩 面试必澄清项（每条配一个追问）
1. {风险点} → 建议追问：「{具体问题}」
2. …

### 稳定性观察
- 任期模式：
- 空档/重叠：

### 交接
- 追问清单可直接喂 loop-interview-writer 的 Mock 模式，设计一场「验证这份简历」的面试。
```

## 多候选人对比

同岗位多份简历一起审阅时启用。前提：**同一目标画像 + 同一 audit rubric**；禁止跨岗位比分（画像不同不可比）。

协议：
1. 逐份先各自跑单人 Audit（声称清单 + 打分 + 🚩），不要为了凑对比省掉单人审。
2. 汇总成对比表（下模板）：分数用于排序，分维度用于看「谁强在哪」。
3. 差异化追问：不同候选人 🚩 不同，对比阶段要指出「各自最该验的那一条」，不是套同一份题。
4. 综合建议按 Audit 分排序，但显式声明**排序非拍板**——最终看 🚩 澄清后的结果。

### 对比报告模板

```markdown
## 多候选人对比 · 目标岗位 {岗位}
（JD 状态：完整 / 仅岗位名画像 · N 位候选）

### 对比表
| 候选 | Audit 分 | 岗位匹配 | 成果可信 | 真实性风险 | 稳定性 | 表达质量 |
|---|---:|---|---|---|---|---|
| {代号} | {N} | 强/中/弱 | … | … | … | … |

### 分维度谁强在哪
- 岗位匹配：{排序 + 一句依据}
- 成果可信：…
- （其余维度按对比有意义的列，无差异的可略）

### 各自最该验的一条（差异化追问）
- {代号 A}：{最关键 🚩} → 追问「{问题}」
- {代号 B}：…

### 综合建议（排序非拍板）
1. {代号}：{约面/观望 + 面试重点验证项}
2. …
```

多份简历一次给全时默认走本对比模式；只给一份走单人 Audit。
